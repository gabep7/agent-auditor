# Agent Auditor

Adversarial red-team testing for AI agents. Finds vulnerabilities before attackers do.

Google Cloud Rapid Agent Hackathon, Arize Track.

## What it does

Agent Auditor is a security testing system for AI agents. Point it at any agent endpoint and it will:

1. Probe the agent's attack surface (8 exploratory requests)
2. Generate adaptive adversarial scenarios using Gemini
3. Run each scenario, including multi-turn conversations
4. Score every response with an LLM judge
5. Generate code-level remediation suggestions for each vulnerability
6. Trace everything to Arize Phoenix and persist results in SQLite

**Attack categories:** parameter manipulation, prompt injection, contradictory instructions, edge cases, multi-turn confusion, tool misuse, indirect injection, prompt extraction, context exhaustion.

**Built-in victims:**

| Victim | Type | What it tests |
|---|---|---|
| `customer_support` | Keyword matcher | Baseline, no validation |
| `banking` | Keyword matcher | PII leakage, financial tools |
| `enterprise_support` | Real ADK agent (Gemini 2.5 Flash) | Realistic vulnerability (OWASP LLM05:2025, Excessive Agency) |
| `custom` | External HTTP | Bring your own agent |

## Architecture

```text
Auditor (ADK + Gemini) ---> Target Agent
  |                              |
  |---> Phoenix MCP (introspect) |
  |                              |
  v                              v
Phoenix Cloud (traces + evals)  SQLite (history)
  |
  v
React UI (dashboard, live stream, reports)
```

The auditor agent uses Google ADK with Gemini 2.5 Flash. It loads the Phoenix MCP server to query past audit traces, ranks attack categories by historical vulnerability rate, and feeds that into scenario generation. Each round is scored by the LLM judge, and results stream to the frontend in real time.

## Tech stack

- **Agent runtime:** Google ADK + Gemini 2.5 Flash
- **Observability:** Arize Phoenix Cloud, OpenInference, Phoenix MCP
- **Evaluation:** LLM-as-judge (Gemini 2.5 Flash) with OTel span annotations
- **Backend:** FastAPI, Python 3.11+
- **Storage:** SQLite
- **Frontend:** React 19, Tailwind CSS 4

## Quick start

```bash
# Backend
cd backend
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# fill in GOOGLE_API_KEY, PHOENIX_API_KEY, PHOENIX_COLLECTOR_ENDPOINT
uvicorn app.main:app --reload

# Frontend
cd frontend
npm install
npm run dev
```

Open http://localhost:5173, select a target, and hit Launch Audit.

### Environment variables

```
GOOGLE_API_KEY=...
PHOENIX_COLLECTOR_ENDPOINT=https://app.phoenix.arize.com/s/<your-tenant>
PHOENIX_API_KEY=...
PHOENIX_PROJECT_NAME=agent-auditor
```

`npx` must be on PATH for Phoenix MCP. If unavailable, the auditor works without it.

## Arize track alignment

| Criterion | How this project addresses it |
|---|---|
| Tracing | `phoenix.otel.register(auto_instrument=True)` instruments the full ADK runtime. Every audit, probe, scenario, and judge call generates OpenInference spans. |
| Phoenix MCP | The auditor loads `@arizeai/phoenix-mcp` as an MCPToolset for direct access to projects, spans, datasets, and annotations. |
| Self-improvement | `adapt_scenarios_from_history` queries Phoenix for past traces, ranks categories by vulnerability rate, and biases the next audit accordingly. |
| LLM-as-judge | Gemini 2.5 Flash scores each scenario with calibrated anchors. Results are written to OTel spans. |
| Real agent testing | The enterprise victim is a real ADK agent with FunctionTool calls, not a keyword stub. |
| Multi-turn | The auditor holds 3+ turn conversations, exploiting context trust. The judge evaluates the full conversation. |
| Remediation | Every vulnerability gets a code-level fix suggestion generated by Gemini. |
| Persistence | SQLite storage with trend charts showing score evolution over time. |
